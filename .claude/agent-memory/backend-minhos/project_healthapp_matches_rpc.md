Possible matches live in `supabase/sql/005_matches.sql` (RPCs), `006_seed_match_cohort.sql` and `007_seed_match_persona.sql`
(both generated by `scripts/synthetic/seed_sql.py`; 007 is the dev persona's synthetic record). Shapes: `RPCS` in
`supabase/functions/_shared/contract.ts`. Applied to `healthapp_dev` 14 Nov 2026; `healthapp_demo` waits for the CTO's real-data gate.

**Why:** F2 (doctor sees matches) and F1 (patient opt-in) for the hackathon demo.

**How to apply:**
- `profiles` is column-granted since 010 (MIN-4484): `matching_opt_in` is readable by no client role, on purpose
  (a doctor in a grant must not learn the flag). Anything the patient needs from a hidden column goes through a
  security-definer getter (`healthapp_get_matches_opt_in`), never a wider column grant.
- No psql and no DB URL on this Mac: SQL reaches conductor only through the Supabase connector's `execute_sql`.
  Prove a transcribed apply with hashes, not by eye: `md5(prosrc)` per function vs the file's `$$` bodies, and
  `md5(string_agg(...))` over a seeded table vs the same serialisation computed in Python from the source JSON.
- To test a path and leave nothing behind, run it in a `do` block that ends with `raise exception '<result>'`:
  the error carries the evidence and the whole block rolls back (used for the rare-pattern check and a mutant).
- Real-token checks: GoTrue password sign-in with `HEALTHAPP_PERSONA_PASSWORD` (`~/.claude/.env.agents`), then
  `POST /rest/v1/rpc/<fn>` with `Content-Profile: healthapp_<env>`. A test grant for the persona pair blocks the
  handshake's unique open-grant index (`grants_open_pair_idx`): delete it the moment the check is done.
- A session hook may confine Write/Edit to the coordinator's worktree; then work in a `git archive` export in the
  scratchpad and commit with plumbing (`GIT_INDEX_FILE`, `commit-tree`, `branch`) instead of writing into another worktree.
